Mac 导出照片怎么整理？按年月归档，保留 Live Photo，分离重复文件

通过 Gallery Organizer 的本地网页和 TUI 交互菜单，预览并执行两轮照片整理，检查 Live Photo 配对、重复副本与日期异常。

本文介绍怎样在 Mac 上用 Gallery Organizer 的本地图形页面或 TUI 整理已导出的照片：先查看移动计划，再按拍摄年月归档，并检查 Live Photo 配对、重复副本和日期异常。

导出以后，照片还需要怎么整理

手机和相机都会重复使用 IMG_0001 这样的文件名。几次导出重叠后，同名文件可能拍摄于不同年份，也可能是同一张照片的副本。Live Photo 常被导出为一张 HEIC 加一段 MOV，旁边还可能有保存编辑信息的 .aae 或 .xmp。只按文件名移动容易拆散配对，只按修改时间归档又可能把复制当天当成拍摄日期。

Gallery Organizer 先整理能确认的相机素材，再处理留下的截图和录屏，以及下载图片和信息有冲突的文件。它仅在 macOS 上运行，处理的是已经导出的文件夹。先从 iPhone 或 Apple 照片 App 导出素材，再交给它；不要直接选择照片图库包。

喜欢看图和点击按钮，可以用本地网页；习惯留在终端，可以用 TUI，也就是终端里的交互提示和按键菜单。两种入口都能先预览再执行，照片留在自己的 Mac 上。

先准备一个批次和输出目录

先独立备份原始导出，拿一小批熟悉的照片试用。下载并解压项目后，用文本编辑器打开 config.ini，把 backup_root 设为自己的照片整理根目录。使用外接盘时，可以填写盘内的专用文件夹，其余子目录先沿用默认值。

例如根目录采用默认位置，结构可以这样理解：

~/Pictures/GalleryOrganizer/
├── Incoming/
│   ├── Stage0/Batch A/       ← 第一轮开始前放入这一批照片
│   └── Stage1/Batch A/       ← 第一轮成功后整批目录移到这里
└── Gallery/
    ├── Main/                 ← 第一轮确认的相机素材
    ├── SortedFromUnsorted/   ← 第二轮认出的相机素材
    ├── Screenshots/          ← 截图与录屏
    ├── OtherMedia/           ← 保存、下载等其他素材
    ├── NeedsRepair/          ← 日期或伴随文件待检查
    └── Duplicate/            ← 确认重复的副本

Stage0/Batch A 和 Stage1/Batch A 表示同一批次在不同阶段的位置。开始时把素材放到 Stage0 的批次文件夹，选择这个批次作为输入；第一轮成功后，再处理 Stage1 中留下的文件。图中的分类目录按需生成，不代表每次都会全部出现。

gallery_root = Gallery 相对于 backup_root，main_library_root = Main 又相对于 Gallery。拍摄时间明确的素材通常进入 Main/2024/2024-06/；同名但内容不同的文件不会互相覆盖，必要时再加日期目录。配置文件里的路径有空格也不用加引号，来源和分类目标都应放在配置的根目录内。

要用中文终端提示和新建分类目录，在 [general] 中设置 language = zh。切换语言不会重命名已有目录，网页上的界面语言则可以另外切换。

启动本地图形页面

在项目文件夹打开终端，首次使用时建立环境并安装网页所需的依赖：

1
2
3
4

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-api.txt
uvicorn api.app:app --host 127.0.0.1 --port 8000

浏览器打开 http://127.0.0.1:8000/，使用期间保留终端窗口。以后重新启动时，在同一个项目目录激活 .venv，再运行最后一条命令即可。

这些 Python 包提供网页服务；媒体读取还会用到外部程序。扫描提示缺少工具时，检查 config.ini 的 [tools]：留空表示从系统查找，也可以填写已安装可执行文件的完整路径。

在网页上完成两轮整理

先在工具下拉框选择主整理器（Main organizer），输入 Incoming/Stage0/Batch A 的完整路径。批大小通常保持默认值，点击扫描 / 预览（Scan / Dry Run）。预览不移动或修改媒体，可以先看目标位置和待检查项（见图 1）。

图 1：选择工具与批次目录，先扫描，再查看整理计划。截图来自项目仓库。

第一遍重点看拍摄年月是否符合记忆、Live Photo 的照片与短视频是否成组，以及同名冲突和重复副本怎样处理。比如 IMG_0100.HEIC、IMG_0100.MOV 和能确认归属的 .xmp 应尽量一起整理；无法配对的伴随文件需要继续核对。

确认计划后，点击执行整理（Apply changes），在弹窗中核对来源目录并确认。工具会重新扫描、检查目标，再执行移动。等任务结束，查看执行结果是否有失败，再到目标文件夹抽查照片和视频。

第一轮顺利完成后，整批目录移到 Stage1。网页上改选剩余媒体整理（第二阶段），把来源换成 Incoming/Stage1/Batch A，再走一次预览和执行。截图与录屏进入 Screenshots，保存的图片等进入 OtherMedia；第二轮确认的相机素材进入 SortedFromUnsorted，日期或关联仍有问题的文件留待检查。

两轮需要分别启动。第一轮的执行结果不代表剩余素材也已整理完，查看 Stage1 和第二轮报告，才能知道还有什么需要处理。

在图形页面检查重复项和日期

网页还提供主库重复检查与JPEG 元数据修复。前者选择配置的主图库内目录，检查已经归档的重复副本；后者用于有足够证据的缺失日期修复。它们都按需要单独运行，继续采用先预览、后确认的方式。

需要看重复图片时，勾选显示重复图片预览（并排对比），再结合路径检查候选图与保留图（见图 2）。这个选项默认关闭，刷新后也会关闭；HEIC 首次生成预览可能较慢。图片无法显示时，仍可查看路径和文字报告。

图 2：用图片对照辅助核对，同时检查保留位置与整理报告。截图来自项目仓库。

完全重复的副本可以单独隔离；连拍、修图版和不同格式的导出仍值得查看内容。JPEG 日期修复前，要在配置中确认 utc_offset、auto_from 和 auto_through，保留原文件备份与修复报告。日期没有依据时，先留在待检查目录。

用 TUI 在终端里操作

TUI 使用文字提示和按键选择。先进入项目目录，运行下面这条命令，不追加目录参数：

1

python3 organize_gallery_media.py

出现输入目录的提示后，把 Finder 中 Stage0/Batch A 文件夹拖进终端，再按回车；也可以输入完整路径。路径无效或超出配置范围时，程序会提示重新输入。

接下来选择运行模式。按回车走默认 DRY RUN，先阅读扫描报告。模式选择时按 A 会直接开始移动文件，第一次操作应先预览。预览结束后，再决定下一步：

预览结束后的按键 作用
A 对同一目录重新扫描并执行 APPLY
Q 退出
其他键 回到开始界面，重新输入目录

按 A 执行后，等报告结束再核对结果。返回开始界面不会撤销已经完成的移动。目录输入阶段可以用 Ctrl+C 退出；上表的 Q 指的是预览结束后的选择。

第一轮成功后，另行启动第二轮 TUI：

1

python3 organize_leftover_media.py

这次拖入 Stage1 中的同一批次，同样先按回车预览，核对后按 A 重新扫描并执行；预览结果页按 Q 退出。第二轮不会自动替你选择第一轮留下的目录，输入前先在 Finder 确认它的位置。

整理结束后再检查一遍

网页的本机任务历史可以打开旧结果，重启服务后仍会保留。记录中的预览和实际执行要分开看；任务若中断，先检查报告与文件位置，再决定是否重跑。工具目前没有整批撤销，也不会自动续跑中断任务。

网页和终端共用执行保护，同一时间只允许一个任务修改文件。看到已有任务执行的提示时，等它完成再继续。网页操作结束后，再到启动服务的终端按 Ctrl+C 停止服务。

最后抽查 Main 中的拍摄年月，确认 Live Photo 还能配对，并查看 NeedsRepair 和重复文件目录。.aae、.xmp 等伴随文件可能保存编辑信息，.thm 和 .lrv 也可能属于相机素材，先保留到关联核对完毕。想检查某张照片的拍摄字段，可配合 View Media Info；完整配置见 项目 README。
