MixTeX for Mac: Turn Formula Images into Editable LaTeX

Find the macOS MixTeX package and understand its formula, mixed-text, and simple-table OCR workflow, including documentation and recognition limits.

MixTeX converts images containing printed formulas, mixed Chinese-English text, and simple tables into editable LaTeX, with a macOS package available in this repository’s Releases.

For research notes, the difficult part of copying a formula is often its structure: a fraction inside a summation, a subscript that belongs to the next symbol, or a table whose alignment matters. OCR can provide a draft of that structure, leaving you to verify it against the original.

MixTeX-Latex-OCR-MacOS is a fork of RQLuo/MixTeX-Latex-OCR. The recognition model comes from upstream; this fork supplies a macOS installer.

Download the Mac release

Open the MixTeX-v3.2.4macOS release and download MixTex.dmg. The release notes describe mounting the disk image and dragging the app into Applications.

The repository’s general README still contains Windows-specific instructions, including Win+V. Those are not Mac shortcuts. Use the Mac release as the installation entry point rather than following the Windows walkthrough literally.

The release page does not list a complete macOS and CPU compatibility table. Launch the app on your own Mac and try one clear formula crop before using it in daily work.

Start with a small, clear crop

Use a clean image of one printed formula or a small text-and-formula block. Keep subscripts, superscripts, and equation boundaries inside the crop. Large page captures, tiny characters, and adjacent columns create more ambiguity.

The project example below shows how an image can become editable LaTeX.

After recognition, paste the LaTeX into a scratch document and render it. Compare the rendered equation with the source image rather than checking only whether the code compiles.

If the source is a paper PDF, export its page as an image and crop the formula rather than including the page number, surrounding column, and neighbouring equations. Keep the crop beside the generated code. When x_1 turns into x_l, you can check the source immediately instead of discovering the error in your notes later.

Send an image to the clipboard on Mac

The graphical interface reads an image from the clipboard and writes recognized LaTeX back as text. The workflow is copy image, wait for recognition, then paste code. The Windows README’s Win+V instructions are not the Mac shortcut sequence.

With MixTeX running, press Control-Shift-Command-4 and select one formula to copy the screenshot directly to the clipboard. Wait for the output, switch to your editor, and paste with ⌘V. Ordinary Shift-Command-4 generally saves a screenshot file instead. Copying that file in Finder is not necessarily the image data the application expects.

Begin with one simple equation. If nothing appears, check the clipboard input and any model-loading or image error shown in the window. Avoid capturing several images during initialization. Waiting for each result keeps its source clear. Since recognition replaces clipboard contents with text, save anything you needed from the previous clipboard first.

Inspect the recognized text’s outer math environment. If it already includes \[ ... \] or an align* block, do not blindly nest it inside another display-math wrapper. A compilation failure can come from duplicate wrappers even when the expression is readable.

For an undefined command, inspect the named command and determine whether it needs a package, contains a typo, or was misrecognized. Deleting a symbol just to make compilation proceed can change the meaning. Once the minimal document works, move the expression into your notes or paper template. For Chinese text, use an environment supporting the README’s ctexart example.

Split a dense page into logical pieces

For a two-column paper or a long derivation, crop complete expressions separately. Too tight a crop can remove integral limits; too wide a crop can include neighboring text. Keep one full expression and its necessary punctuation so each result has a clear source.

Check alignment and line breaks in multi-line derivations. A term moving to the next line may still compile while changing how the equation is read. For tables, verify row and column correspondence as well as individual numbers. Place the original crop beside the rendered result and compare line by line before copying it into a final document.

Keep the paper title, page number, and crop with long-term research notes. If you later question a subscript or need the original derivation, you can return to the source immediately. OCR saves transcription time; retaining that source keeps the editable result useful.

Check mathematical meaning

Small OCR changes can alter an equation while leaving it syntactically valid. Check minus signs, equality and inequality signs, indices, Greek letters, brackets, and matrix dimensions.

Tables need separate attention. A table that looks plausible can still have a value in the wrong row or column. Treat OCR as assisted transcription, especially when the output will appear in an assignment, paper, or calculation.

The Chinese README limits the intended input to clear printed Chinese/English text, formulas, and relatively simple tables. Do not assume support for handwriting, arbitrary languages, or complex table reconstruction.

Local inference and practical setup

The upstream project describes CPU-based local inference. That is useful for a workflow that should not require sending each screenshot to an online recognition service, although installation can still require obtaining the application, model files, or dependencies.

Rendering the result also requires a suitable LaTeX setup. For Chinese text, the README suggests a document using ctexart; mathematical output may need packages such as amsmath and amssymb.

If your source is a PDF, PDF Page Extractor can first export a page as an image. Keep the PDF and original crop beside the recognized text so corrections remain easy to verify. The Chinese README documents recognition limits more directly than the repository’s short description.
